PR Portal Inspector & Action Recorder

Help guide: features, how to use the app, and precautions for safe recording.

This guide describes the current packaged application. It is an observation and workflow-development aid, not a finished PR approval automation.

1. What the app does

  • Opens a separate Playwright-controlled browser for the portal.
  • Inspects the current page and reports visible controls, candidate selectors, dropdown options, table headings, sample rows and visible text.
  • Records observed navigation, clicks, field changes, selected text, and supported controls hovered for more than four seconds.
  • Shows a numbered event sequence in the GUI and marks captured interactions in the browser.
  • Saves compressed browser-screen frames at captured interactions and approximately every two seconds. The frames include the visible yellow click/selection circles and can be reviewed in Sequence & Playback. This is a frame sequence, not a continuous video.
  • Plays back the captured sequence visually, highlighting components and showing saved screen frames. Playback is for review; it does not replay the original clicks or submit forms.
  • Saves JSON workflow captures and lists previous recordings with date/time, age in days, component counts by type and event totals.
  • Can show a draft Playwright JavaScript workflow for review. The draft is only a starting point; selectors and logic must be checked before use.
  • Provides an optional login-field helper that attempts to fill detected user ID and password fields. It does not submit the login form.
  • Uses a compact, responsive, PWA-style web interface. A supported browser may offer installation when the app is served from localhost.

2. Start the application

  1. Extract the complete ZIP into a normal folder, for example C:\PR_Status_Automation\PR_Portal_Inspector_Recorder.
  2. Double-click Start-Here.hta.
  3. Press Start Inspector in the launcher. If the HTA is blocked by Windows or office policy, try Start-App.bat.
  4. The first run needs Node.js LTS installed and internet access so dependencies and Playwright Chromium can be installed.
  5. Open http://127.0.0.1:3030 if it does not open automatically.
  6. Keep the server window open while using the app. Close the server window when finished.
The launcher is the simple start method. A normal browser HTML page cannot start a local Node.js server by itself, so the local HTA or batch helper is required.

3. Feature-by-feature guide

Navigate the new sidebar

The main GUI opens on Overview. The sidebar is expanded by default. Use the hamburger button to collapse or expand it, and the pin button to keep it open. Choose a tab to show one workspace area at a time: Portal & Login, Inspect Page, Record Workflow, Sequence & Playback, Export & Draft, and Past Recordings. Select Help & Safety to reopen this guide.

Overview and live activity

The Overview shows browser status, recording status, the number of captured steps and saved recordings. The Live activity feed displays important events such as opening the portal, inspection results, recording start/stop, and newly captured sequence steps. Clear only clears the on-screen activity feed; it does not delete your recording files.

Open the portal

The Portal URL field is prefilled with the JSW Ariba URL supplied for this app. If its awssk query parameter is session-specific or expires, replace it with the current authorized portal URL. Select Open in Playwright browser. This browser has a separate session from your normal Chrome or Edge, so you may need to sign in again. Refresh status updates the app's browser and recording status indicators.

Optional login helper

Enter your user ID and password in the app and choose Fill login fields. The helper tries to detect a username-like field and password field and fill them. It does not press the portal's login button. If the page uses a complex sign-in flow, sign in manually in the Playwright browser. Clear credentials from the GUI when finished.

Inspect current page

Navigate to the page you want to understand, then click Inspect current page. The results can include control index, element type, label/text, visibility, enabled state, candidate selector and dropdown options. Tables may show headings, row counts and sample rows. The visible-page-text panel helps locate relevant wording. Use Download inspection JSON to save the inspection report.

Record navigation and interactions

  1. Enter a recording name in the sidebar field above Overview, or in Record Workflow. This is required for every recording.
  2. Click Start in the sidebar or Start recording in Record Workflow. The sidebar also has a Stop button.
  3. Perform the workflow manually in the Playwright browser. The app records supported clicks, input changes and navigation events. It can also capture selected text and supported controls hovered for over four seconds.
  4. At a branch or important point, enter a short note and choose Add decision marker. Example: “Status shows pending at level 2; opened release strategy.”
  5. Click Stop in the sidebar or Stop recording. The JSON recording and a matching *_frames folder are saved automatically in output. Frames are captured when events occur and about every two seconds; yellow markers visible at capture time are included in the images.

Live sequence and visual markers

Captured events appear in the sequence list with step numbers, event type, component tag, selector (when available) and timestamp. The same element type uses a consistent type-based colour. Clicks and selected-text events are marked with yellow numbered circles in the portal page; captured hover events are also shown as highlights. The exact highlight may depend on whether the component is still present on the current page.

Playback

Stop recording before playback. The Recorded Playwright screen panel displays saved screenshots with yellow circles; thumbnails can be selected, and Play sequence advances the screen frame along with the observation timeline. Click Play sequence to step through the observation timeline; use Pause/Resume or Stop playback as needed. The current step is highlighted in the GUI and the browser attempts to highlight the matching component. Screen capture is a sequence of compressed snapshots, not a continuous video file. For recorded URLs on the same origin, playback may navigate to the recorded URL. It does not repeat clicks, change fields or submit forms. If the page has changed since recording, some components may not be found.

Export and draft code

Download workflow capture JSON exports the observation log. Show Playwright draft displays a candidate script, and Download latest draft JS downloads it. Treat the draft as a review aid only: selectors may be unstable, dynamic pages may behave differently, and additional error handling and validation may be needed.

Past recordings

Past recordings appear in the history list after stopping a recording. The list includes recording name/file, date and time, days since recorded, components inspected by type, components used/interacted with by type, event counts and a JSON download link. Choose Refresh past recordings to reload the list. Older captures can have fewer inspection details if they were recorded before those details were stored. To carry history into a new installation, copy the relevant *_workflow_capture.json files into that version's output folder.

4. Suggested workflow for finding a pending PR approver

  1. Open the portal and sign in.
  2. Start a clearly named recording, such as PR_Pending_Approval_Path.
  3. Search for one test PR and open its details.
  4. Use Inspect current page on the relevant screens, especially release strategy or approval status.
  5. Navigate to the visible approval/pending section. Add a decision marker explaining what the screen says.
  6. Stop the recording, inspect the sequence and play it back visually.
  7. Save the JSON and inspection output. Review the captured names, internal URLs and business data before sharing them.
  8. Verify the result against the portal manually before using any generated code on a list of PRs.
Begin with one PR. Confirm exactly how the portal indicates “pending with” before processing a larger Excel list.

6. Important precautions

Read-only caution: The tool has browser-side guards for common state-changing actions, but it cannot guarantee every portal action is harmless. Do not click Approve, Release, Reject, Delete, Save, Submit or other actions that may modify a PR. The safest approach is to navigate manually and avoid write actions entirely.
  • Use this tool only on systems and data you are authorized to access.
  • Never share passwords, one-time codes, session cookies, access tokens or other secrets. Do not put secrets into notes.
  • The app does not intentionally include credentials in recording exports, but recordings may contain PR numbers, employee names, internal URLs, selected text and business information. Inspect files before sharing.
  • Keep the app on its local address 127.0.0.1; do not expose the local server to a public network.
  • Use a test or low-risk PR when learning the workflow. Verify the screen's meaning instead of relying on a guessed selector.
  • Selectors such as generated IDs may change between sessions. Validate them and prefer stable labels/roles/text when developing final automation.
  • Visual playback is not proof that an action would work again. It may fail to find a component if the page layout, data, session or URL has changed.
  • Stop recording before playback. Do not use playback as an approval robot; it is a visual review feature only.
  • Keep each *_frames folder together with its matching JSON file; the JSON stores references to the screenshots, not the image data itself.
  • Screen frames can include internal pages, PR values, employee names and other sensitive portal content. Review them before sharing.
  • Keep a backup of recordings before replacing or deleting an app folder.

7. Troubleshooting

Excel input queue (new)

  1. Use the Drop Excel here zone in the left sidebar, or choose Browse file.
  2. Supported formats: .xlsx, .xls and .csv. Maximum file size: 15 MB.
  3. Open the Excel Queue tab to review worksheet names, column headers, row counts and the first few rows.
  4. The uploaded workbook is stored locally in the app's input folder. Do not upload files containing unrelated sensitive information.

Important: This is workbook intake and preview only. It does not process rows against the portal yet. Before enabling row-by-row automation, define the PR-number column, required extracted fields, output format, duplicate/blank-row handling, and error/retry behaviour. Test on a small non-sensitive workbook first.

Portable runtime and first-time setup

This package uses a private Node.js runtime under runtime\node, app dependencies under node_modules, and Playwright Chromium under browsers. You do not need to install Node.js globally. On first launch, the launcher downloads the official Windows x64 Node.js ZIP and retrieves app dependencies and Chromium. This first setup needs internet access and may be blocked by an office proxy or security policy. After setup, keep the entire folder together; it can be copied to another folder or PC with its runtime, dependencies, browser, input, and output folders intact.

Do not delete runtime, node_modules, or browsers. If setup is incomplete, reconnect to the internet and run Start-App.bat again. No global Node.js installation is changed.
